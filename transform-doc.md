# transform.go

A standalone Go program that transforms MATLAB code coverage HTML reports into cleaner, more readable documents.

## Requirements

- Go 1.21 or later (standard library only, no external modules)

## Usage

```
go run transform.go <input.html> <output.html>
```

Or compile first:

```
go build -o transform.exe transform.go
./transform.exe code-coverage-report.html code-coverage-report-new.html
```

## Input

A self-contained HTML file generated by the MATLAB Report Generator's code coverage tool. The expected structure includes:

- An Overall Summary table (Coverage Metric / Executable / Missed / Justified / Coverage %)
- A Table of Contents table listing each source file with Function and Statement coverage sub-columns
- Per-file sections, each containing:
  - A summary table with coverage statistics
  - A code lines table (Line / Function / Statement / Source Code / Justification)

## Output

A transformed self-contained HTML file with the same overall structure but improved readability and reduced file size.

## Transformations

The program applies six transformations in order:

### 1. Fix CSS fonts (`fixCSSFonts`)

Replaces the serif font `Cambria` in heading styles (h1-h6) with `'Segoe UI'` and ensures all font stacks include a `sans-serif` generic fallback. Also normalizes the body and table font-family declarations.

### 2. Inject new CSS rules (`injectCSS`)

Adds styles for:
- `<details>` / `<summary>` accordion elements (cursor, font, color)
- `.uncovered` row highlighting (light red background `#ffdddd`)

Rules are injected into the existing `<style>` block to keep the file self-contained.

### 3. Strip redundant inline styles (`stripInlineStyles`)

Removes thousands of repeated inline `font-family` and `font-size:12pt` declarations from element `style` attributes. These are redundant because the CSS body rule already defines the same values. Also removes empty `style=""` attributes left behind after stripping.

This step accounts for most of the file size reduction.

### 4. Remove Justification columns (`removeJustificationColumns`)

Removes the "Justified" / "Justification" column from all tables:

| Table | Column removed |
|-------|----------------|
| Overall Summary | "Justified" (4th column) |
| Table of Contents | "Justified" under both Function and Statement groups; reduces colspan from 4 to 3 |
| Per-file summary | "Justified: N" text lines |
| Per-file code tables | "Justification" (5th/last column) |

### 5. Wrap code tables in accordions (`wrapCodeTablesInDetails`)

Each per-file source code table (identified by `width:18in` and Line/Function/Statement/Source Code headers) is wrapped in an HTML5 `<details><summary>Source Lines</summary>...</details>` element.

Tables are collapsed by default. No JavaScript is needed; the native `<details>` element handles expand/collapse.

### 6. Highlight uncovered lines (`highlightUncoveredLines`)

In code line tables, rows where the Statement column contains `0` are marked with `class="uncovered"`. The injected CSS rule gives these rows a light red background (`#ffdddd`).

## Helper Functions

| Function | Purpose |
|----------|---------|
| `removeNthTd(row, n)` | Removes the nth (0-indexed) `<td>...</td>` element from a table row |
| `removeLastTd(row)` | Removes the last `<td>...</td>` from a row and cleans up the right border on the new last cell |

## Typical Results

| Metric | Before | After |
|--------|--------|-------|
| File size | ~2.0 MB | ~1.4 MB |
| Justification/Justified mentions | 18 / 18+ | 0 |
| Serif font references (Cambria) | 6 | 0 |
| Redundant inline font-family | thousands | 0 |
| Accordion wrappers | 0 | 18 |
| Highlighted uncovered rows | 0 | varies (depends on coverage) |

## Limitations

- Assumes the input follows the exact structure produced by the MATLAB Report Generator's code coverage template. Changes to the report generator's output format may require updating the string patterns and regular expressions.
- Processing is done entirely in memory. Very large reports (hundreds of MB) may require significant RAM.
- The program does not validate HTML correctness of the output. It relies on precise pattern matching of the known input structure.
